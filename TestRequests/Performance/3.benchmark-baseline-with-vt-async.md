## 🔬 Implementation Changes

---

### ✅ 1. Introduced Async Service

```java
@Async
public void saveEventAsync(TelemetryEvent entity) {
    repository.save(entity);
}
````

***

### ✅ 2. Controller Flow Updated

Before:

    Request → DB save → Response

After:

    Request → Async trigger → Immediate Response
                      ↳ DB write in background

***

### ✅ 3. Enabled Virtual Threads

```yaml
spring:
  threads:
    virtual:
      enabled: true
```

***

### ✅ 4. Configured ExecutorService

```java

@Bean(name = "taskExecutor")
public Executor taskExecutor() {
    return Executors.newVirtualThreadPerTaskExecutor();
}
```

***

## 🧠 Key Insights

***

### ✅ 1. Async Removed Request Blocking

Before:

    Request waits for DB ❌

After:

    Request returns immediately ✅
    DB write happens in background ✅

***

### ✅ 2. Virtual Threads Eliminated Thread Bottleneck

* Lightweight execution model
* No thread pool exhaustion
* Efficient scheduling

***

### ✅ 3. ExecutorService Improved Scheduling

* Reduced overhead from default async executor
* Efficient task handling
* Improved overall throughput

***

### ✅ 4. System Bottleneck Shifted

> ❗ Critical Insight:

System moved from:

    Thread-bound → I/O-bound ✅

***

### ✅ 5. Database is Now the Limiting Factor

Observed:

* Throughput plateau (\~14 req/sec)
* Latency improvements no longer significant

***

👉 Root cause:

    DB write latency
    Connection pool limits
    Disk I/O

***

## ⚠️ Architectural Tradeoffs

***

### ✅ Pros

* Very low API latency ✅
* High concurrency support ✅
* Scalable thread handling ✅
* Clean separation of concerns ✅

***

### ⚠️ Cons
